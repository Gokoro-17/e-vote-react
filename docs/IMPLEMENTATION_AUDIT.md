# E-Vote requirement audit

Audit date: 3 October 2026. Target: `mdtymdvybaurguflwktt`.

The database contains 31 application tables in the private `evote` schema, with four reviewed migrations applied. Select `evote` in Supabase Table Editor; the tables are intentionally outside `public`. The database-backed API is healthy, and 24 live readiness checks passed against the corrected local API and real Supabase project, including RLS, restricted runtime permissions, bot protection, sign-out cookie clearing, private document storage and ballot/identity separation. Email confirmation is enabled, and Google OAuth redirects to Google with a valid web client. SMTP, Turnstile and required server settings are configured. Supabase Cron drives the protected production maintenance endpoint. Full real-account sign-in, confirmation-email delivery, password recovery, ballot/payment acceptance and rendered device testing remain unverified.

The latest instruction overrides section 43: no fictional seed data or generated database test fixtures. The old local records, cluster, document files, and recovery copies were removed. Pure computation tests remain as source and do not seed application data.
